### 2. Instalacion de `uv`
Instalamos `uv`, el gestor de paquetes y entornos virtuales de Python moderno (de Astral, los mismos que hacen `ruff`).

**Por que:** El MCP de AutoCAD (`autocad-mcp`) usa `uv` para manejar sus dependencias. Sin `uv` no podemos instalar ni correr el MCP.

**Como lo instalamos:** El metodo de `winget` no funciono bien porque no actualizo el PATH correctamente. Terminamos usando el instalador oficial de PowerShell:
```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

---

### 3. Clonado e instalacion del MCP de AutoCAD
Clonamos el repositorio `puran-water/autocad-mcp` dentro del proyecto y corrimos `uv sync` para instalar todas sus dependencias.

```powershell
cd "C:\Users\lucas\OneDrive\Escritorio\Point.ai"
git clone https://github.com/puran-water/autocad-mcp.git
cd autocad-mcp
uv sync
```

**Por que:** El MCP (Model Context Protocol) es el puente entre Claude y AutoCAD. Sin el, Claude no puede darle instrucciones a AutoCAD. Es la pieza mas critica de toda la arquitectura — sin el MCP no existe ninguno de los 3 sistemas.

El repositorio `autocad-mcp` expone 8 herramientas que Claude puede usar para controlar AutoCAD en tiempo real: crear capas, dibujar paredes, insertar bloques, agregar dimensiones, tomar screenshots, etc.

### 4. Carga del dispatcher LISP en AutoCAD
Cargamos `mcp_dispatch.lsp` en AutoCAD LT 2024 usando el comando `APPLOAD`.

**Archivo:** `autocad-mcp/lisp-code/mcp_dispatch.lsp`

**Confirmacion:** AutoCAD mostro `=== MCP Dispatch v3.1 loaded ===` en la barra de comandos.

**Por que:** El MCP se comunica con AutoCAD via archivos JSON en `C:/temp`. El `.lsp` es el receptor dentro de AutoCAD — lee esos archivos y ejecuta los comandos. Sin esto, AutoCAD no escucha nada de lo que Claude le manda.

---

### 5. Configuracion del MCP en Claude Code
Creamos el archivo `.mcp.json` en la raiz del proyecto.

**Por que:** Claude Code detecta automaticamente este archivo y lanza el servidor MCP al arrancar. Esto permite que Claude use las herramientas de AutoCAD directamente en la conversacion sin tener que correr nada manualmente.

**Tambien creamos `C:/temp`** — carpeta que el MCP usa para la comunicacion IPC entre Python y AutoCAD (Python escribe un JSON, AutoCAD lo lee y ejecuta, devuelve resultado).

### Resumen de datos que logramos extraer

#### De cada layer (las 52):
| Dato | Como lo sacamos | Resultado |
|---|---|---|
| nombre | MCP layer list | 52 layers |
| color ACI | MCP layer list | Todos |
| linetype | AutoLISP tblnext | Continuous, HIDDEN, WIRE3, CENTER... |
| frozen / locked / off | AutoLISP tblnext flags | Todos en 0 (ninguna congelada/bloqueada) |

| plot | AutoLISP tblobjname+entget | Solo Defpoints = no plotea |

| entity_count | ezdxf | L1=3921, ELECTRICAL WALLS=1035, DIMS=1007... |
| entity_types | ezdxf | Por ej: WALLS → LINE:440, LWPOLYLINE:19 |
| bbox (min/max XY) | ezdxf | Ubicacion espacial de cada layer en el dibujo |

#### Datos especificos por tipo de layer:
| Layer | Dato extra extraido |
|---|---|
| WALLS, DOORS, FIXTURES, WIN | Geometria completa: coordenadas de cada linea, arco, polylinea |
| ROOM LBLS, TEXT, TEXT LBLS, PLAN LABEL | Texto completo: "MASTER", "KITCHEN", "LIVING ROOM", "16x16 COLUMNS"... |
| ELECTRICAL, CABS, CABS-FLOORPLAN | Bloques usados: LT x20, SW x3, RFAN x2, CFANLT x1... |

#### Hallazgos importantes del Seminole 2000 Farmhouse:
- **L1 es la layer mas grande** — 3921 entidades (LINE, LWPOLYLINE, 3DFACE, ARC). Probablemente contiene elementos generales no asignados a layers especificas.
- **Paredes dibujadas con lineas simples** — WALLS usa LINE:440 + LWPOLYLINE:19, no bloques
- **Puertas dibujadas con lineas y arcos** — DOORS: LINE:90 + ARC:49 (el arco es el swing de la puerta)
- **Ventanas son solo lineas** — WINS: LINE:113
- **Electrico usa bloques nombrados** — LT (luz), SW (switch), RFAN (fan), OL, RLT
- **Cuartos identificados**: MASTER, BEDROOM 2, BEDROOM 3, BEDROOM 4, KITCHEN, DINING, LIVING ROOM, GARAGE, BATH, ENTRY, PORCH, PATIO, UTILITY, CLOSET, PWDR
- **El dibujo tiene 3 sheets en un solo modelspace** — Sheet 1: elevaciones, Sheet 2: framing estructural, Sheet 3: floor plan + electrico. Confirmado con screenshot via MCP.

### 9. Descubrimiento clave — el DWG tiene 3 sheets en un solo modelspace

Confirmado con screenshot en vivo via MCP (`view → get_screenshot`): el Seminole 2000 Farmhouse tiene **3 sheets distintas en un mismo modelspace**, cada una posicionada en diferentes coordenadas X del model space. No usa Paper Space layouts (Layout1 esta vacio).

| Sheet | Posicion X aprox | Contenido |
|---|---|---|
| Sheet 1 — Elevaciones | X ~ 58,000–60,000 | Las cuatro fachadas del edificio (FRONT, REAR, LEFT, RIGHT ELEVATION) |
| Sheet 2 — Estructural | X ~ 60,000–62,000 | Framing plan — paredes estructurales (en rojo), techo, secciones |
| Sheet 3 — Floor Plan + Electrico | X ~ 62,000–64,000 | Distribucion de cuartos + sistema electrico superpuesto |

**Importante:** En AutoCAD, "Elevations" = fachadas. FRONT ELEVATION es la fachada delantera, REAR es la trasera, LEFT y RIGHT son los laterales.

**Nota:** El conteo anterior de "5 planos" era incorrecto — venia de analizar clusters de coordenadas X sin verificar visualmente. El screenshot via MCP lo desmintio.

### 10. Implicacion directa para Sistema 1

El Sistema 1 pide: "Carlos sube una imagen de un plano → recibe un DWG en AutoCAD".

Esa imagen solo puede ser la **planta (Floor Plan)**. Las elevaciones/fachadas y el techo requieren criterio tecnico que no esta visible en la imagen.

**El MVP del Sistema 1 genera unicamente el Floor Plan.** El Electrical Plan, Roof Framing y Wall Sections son sistemas separados que vienen despues.
